# Insight Global Job Finder

Searches Insight Global for remote jobs matching configurable tracks:

- **Core stack:** software engineering roles scored against the skills in
  `RESUME_SKILLS`.
- **Growth tracks (Java, iOS, .NET):** junior and entry-level roles in a
  single skill that do not explicitly require more than three years of
  experience.

International/LATAM/India-titled postings are filtered out unless the
listing's country is genuinely the US. Titles naming a stack outside the
resume (Drupal, Android, SAP, Snowflake, etc. — see `NON_RESUME_TITLE_TECH`)
are dropped too, and postings older than `MAX_POSTED_AGE_DAYS` (30) are
excluded. Each emailed job shows its Job ID and req number alongside the
usual details.

Only new matches are emailed. Job IDs are kept in `seen_jobs.json` locally or
in the GitHub repository when the GitHub state variables are configured.

## Install and run

```bash
pipenv install --dev
pipenv run python job_search.py
```

Tune search terms, skills, remote-only behavior, page depth, and matching
thresholds at the top of `job_search.py`.

## Gmail API setup

The bot uses the Gmail API's narrow `gmail.send` OAuth scope instead of an app
password or SMTP.

1. Enable the Gmail API in a Google Cloud project.
2. Configure the OAuth consent screen as **External / Testing** and add your
   Gmail address as a test user.
3. Create a **Desktop app** OAuth client and download it as `credentials.json`.
4. Run the bot locally once. A browser opens for consent and writes
   `token.json`, which contains the reusable refresh token.

Override the paths when needed:

```bash
export GMAIL_CREDENTIALS_PATH=/path/to/credentials.json
export GMAIL_TOKEN_PATH=/path/to/token.json
export IG_EMAIL_TO=you@example.com
```

Copy `.env.example` to `.env` and replace the example recipient if you prefer
file-based configuration; the script loads `.env` automatically. Never commit
`credentials.json`, `token.json`, or `.env`.

## State persistence

Without GitHub configuration, `seen_jobs.json` is updated atomically on the
local filesystem. For an ephemeral cron environment, configure:

```bash
export IG_GITHUB_TOKEN=github_pat_...
export IG_GITHUB_REPO=owner/job-finder
export IG_GIT_BRANCH=main
```

Use a fine-grained token limited to this repository with **Contents: Read and
write**. The bot reads and updates `seen_jobs.json` through the GitHub Contents
API; it does not put the token in a Git remote or invoke Git.

State is saved only after Gmail successfully sends the digest, so a failed
email is retried on the next run.

## Render deployment

`render.yaml` defines a daily cron job at `13:00 UTC`. Create a Render
Blueprint, then:

1. Add secret file `credentials.json` with the OAuth client JSON.
2. Add secret file `token.json` with the token generated by the local run.
3. Set `IG_EMAIL_TO`, `IG_GITHUB_TOKEN`, and `IG_GITHUB_REPO`.

The Blueprint mounts the secret files at `/etc/secrets` and pins Python to the
same version as the Pipfile. Render secret files are read-only; refreshed Gmail
credentials are used in memory without attempting to modify the mounted token.
